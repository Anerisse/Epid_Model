# AGENTS.md

Магистерская диссертация «Моделирование эпидемий». UI-строки и комментарии в коде на русском — сохраняйте это соглашение.

## Стек (после миграции)

Новый стек — клиент **React + TypeScript + Vite + TailwindCSS v4 + shadcn-стиль**, сервер **Next.js (App Router, API-роуты) + локальный SQLite** (`better-sqlite3`). Все тяжёлые вычисления — **на сервере**: разбор ОДУ, РК4, R₀ (NGM), МНК. Клиент только рендерит результаты (графики recharts, блок-схема SVG).

**Два пакета** (по одному `package.json` в каждом каталоге):

- `server/` — Next.js API + SQLite. `npm run dev` / `npm run build` / `npm start`.
- `client/` — Vite + React. `npx vite` (dev с прокси `/api` → 3001) / `npx vite build`.

Старый стек (ванильный JS-клиент + NestJS/Postgres) сохранён без изменений в `legacy/` (`legacy/client`, `legacy/server`) **только как эталон и архив** — не разрабатывается и не запускается. Его тесты (82/82 в legacy) побитово портированы на vitest в `server/core/*.test.ts` (47 тестов).

`docs/`, `diagrams/`, `plan/` — документация и материалы диссертации (docx/pdf/png/drawio), для разработки игнорируйте.

## Запуск приложения

База данных теперь не нужна отдельно (SQLite — файл `server/data/epid.db`, создаётся сам при первом обращении; `data/` в `.gitignore`).

1. Сервер: `cd server && npm install && npm run dev` — слушает **порт 3001** (`next dev -p 3001`).
2. Клиент: `cd client && npm install && npx vite --port 5173` — dev-сервер проксирует `/api` на `http://localhost:3001`.
3. Прод-режим: `cd server && npm run build && npm start` (порт 3001), клиент — `npx vite build` (папка `client/dist/`) раздаётся любым статиком.

Порты: сервер всегда 3001, прокси захардкожен в `client/vite.config.ts`. Менять порт — в обоих местах.

## Архитектура системы

Одна общая система «модель → этапы работы с ней»; **модель (текст ОДУ) — общий контекст** для всех разделов (React-контекст `client/src/lib/model-context.tsx`). Разбор текста выполняет сервер (`POST /api/parse`), клиент дебаунсит запросы.

Маршруты-разделы заданы списком (см. `client/src/components/app-shell.tsx`, роуты в `client/src/App.tsx`):

| Раздел | Маршрут | Сервер | Статус |
|---|---|---|---|
| Модель | `/` | `POST /api/parse` (структура+пресеты+раскладка), CRUD `/api/models` | ✅ сделано |
| Симуляция | `/simulation` | `POST /api/simulate` (РК4 на сервере: время/ряды/статистика + блок R₀) | ✅ сделано |
| Параметризация | `/parametrization` | `POST /api/fit` (МНК, Нелдер–Мид), `POST /api/fit/synthetic` | ✅ сделано |
| Верификация | `/verification` | будущий `POST /api/verify` | 📋 план |
| Анализ чувствительности | `/sensitivity` | будущий `POST /api/sensitivity` | 📋 план |
| Сценарный анализ | `/scenario` | будущий `POST /api/scenario` | 📋 план (соавтор) |

В базовой поставке на каждый этап — по одному алгоритму; клиентские модули (`client/src/pages/*`) изолированы и могут расширяться без затрагивания остальных разделов.

### Сервер (`server/`)

- `core/` — **чистое ядро** (TS, без зависимостей от Next/React), 1-в-1 порт legacy-логики:
  - `parser.ts` — парсер систем ОДУ: `dS/dt`/`∂S/∂t`/`S'`, греческие буквы и алиасы (`beta`→`β`, `mu`→`μ` раньше анализа), алгоритм Пратта, AST, компартменты/параметры/потоки (`inferFlows`), `evaluateExpression`, `lightStructure` (без AST — то, что уходит в БД/на клиент).
  - `presets.ts` — пресеты ползунков (β 0.5/0–2, γ 0.2/0–1, σ 0.3/0–1, μ 0.02/0–0.5, α/δ/ε/λ 0.1/0–1, N 10000/1000–1e5; `GENERIC_PARAM_PRESET` 0.1/0–1; `DEFAULT_POPULATION` 10000).
  - `diagram.ts` — топологическая сортировка (алгоритм Кана), раскладка блоков, цвета; **SVG по координатам рисует клиент** (`client/src/components/block-diagram.tsx`): дуги-стрелки, обход промежуточных блоков дугой сверху, пунктирные янтарные «силы заражения» (движители вроде I в β*S*I/N), потери «в никуда» (µ*X) со стрелкой вниз и «таблеткой» под подписью. Ручные перенаправления потоков — `FLOW_REDIRECTS` (пуст; полноценная редактируемая таблица потоков — далее).
  - `simulate.ts` — РК4 с шагом `SIM_DT = 0.05`, расходимость кидает понятную ошибку; статистика (пик I, день пика, выздоровевшие) и `buildAnalysisReport` — **блок «Качественный анализ»**.
  - `analysis.ts` — R₀ универсально методом NGM по правым частям ОДУ (классификация компартментов с замыканием цепочек, `ρ(F·V⁻¹)`), мини-КАС **символьного вывода «уравнения R₀»** (`derive`, `simplify`, `formulaText`; для 2 заражённых — tr/√(tr²−4det), формула принимается только при совпадении с численным NGM), порог 1/R₀, итог переболевших из `1−x = e^(−R₀·x)`, проверка сохранения популяции, ручная формула `computeR0Manual`.
  - `fit.ts` — МНК: `parseFitData` («день число»/одиночные числа), `fitInitialCondition` (I₀ из первого наблюдения), `simulateAtDays`, `fitCost`, Нелдер–Мид без производных (`nelderMead`, границы из пресетов), `fitParameters` (N подставляется автоматически), `generateSyntheticData` (истинные параметры = пресеты + шум).
- `lib/db.ts` — SQLite (better-sqlite3): таблица `models` (id, name, raw_text, structure JSON-строка, created_at, updated_at; поля API в snake_case), CRUD-хелперы. Путь БД — `server/data/epid.db` (переопределяется `DB_PATH`/`DB_DIR`).
- `app/api/` — роуты App Router, везде `export const dynamic = "force-dynamic"` (без кэширования):
  - `models/route.ts` и `models/[id]/route.ts` — GET/POST и GET/PATCH/DELETE (структуру считает парсер при сохранении).
  - `parse/route.ts` — `{ok, structure(light), presets, diagram}`.
  - `simulate/route.ts` — принимает «сырой» текст + параметры/начальные условия/горизонт/ручную формулу, парсит сам; возвращает `{ok, time, series, names, colors, rhsText, stats, analysis}` (R₀ встроен в ответ симуляции).
  - `fit/route.ts` — `{ok, params, rmse, r2, iterations, time, model(кривая I), points}`; `fit/synthetic/route.ts` — `{ok, text, params}`.
- `next.config.mjs` — `serverExternalPackages: ["better-sqlite3"]` (нативный модуль не бандлится). Порядок скриптов: `dev`/`build`/`start` (`-p 3001`), `test` (vitest `run` в `core/`).

### Клиент (`client/`)

- Vite + React 19 + react-router-dom v7 + recharts + lucide-react + tailwindcss v4 (`@tailwindcss/vite`, тема в `src/index.css` через `@theme`: палитра `ink`, шрифты Manrope/Space Grotesk/JetBrains Mono; стили range-слайдеров `.sim-range`).
- `src/lib/api.ts` — типизированные HTTP-хелперы к `/api` (зеркало серверных типов).
- `src/lib/model-context.tsx` — общий контекст модели: текст+название, автозагрузка последней сохранённой, дебаунс-разбор через `/api/parse`, список сохранённых моделей.
- `src/components/ui/*` — shadcn-стиль Компонентов написаны вручную (cn/cva, без Radix; чекбоксы и слайдеры — нативные).
- Страницы — по разделу: `model-page` (редактор+структура+блок-схема+сохранение), `simulation-page` (слайдеры → `/api/simulate` с дебаунсом 120 мс → графики recharts + статистика + панель R₀ с ручной формулой), `parametrization-page` (наблюдения, чекбоксы «оценивать», слайдеры фиксированных, «Пример» → синтетика, «Оценить» → МНК, кривая+точки на общем графике), `verification/sensitivity/scenario` — заглушки-планы (`plan-placeholder`). Страницы грузятся лениво (`React.lazy`), recharts — в отдельных чанках.

## План развития

1. ✅ **Этап 0** — хранение моделей: таблица `models` + CRUD `/api/models` (SQLite вместо Postgres).
2. ✅ **Этап 1** — парсер ОДУ на сервере (`server/core/parser.ts`) + тесты vitest; разбор SIR/SEIR/…, греческие буквы и алиасы, компартменты/параметры/потоки, `structure` в `models.structure`.
3. ✅ **Этап 2** — авто-блок-схема: раскладка и потоки на сервере (`diagram.ts`), отрисовка SVG на клиенте (`block-diagram.tsx`) — дуги, обходы, пунктирные «силы заражения», потери; ручные перенаправления `FLOW_REDIRECTS` — fallback; редактируемая таблица потоков — далее.
4. ✅ **Этап 3** — интерфейс: тёмная тема, сайдбар-навигация по всем разделам, сохранение/загрузка/удаление моделей.
5. ✅ **Этап 4** — симуляция на сервере: `POST /api/simulate` (РК4 с `dt = 0.05` в `simulate.ts`), графики S/E/I/R в recharts по цветам блок-схемы, статистика (пик I, день пика, выздоровевшие). **Блок «Качественный анализ»** — в том же ответе: R₀ методом NGM (универсально, без ручных формул), символьное «уравнение R₀» (мини-КАС в `analysis.ts`), F/V-матрицы, вердикт, порог 1/R₀, итог переболевших, сохранение популяции, ручная формула как fallback.
6. ✅ **Этап 5** — параметризация на сервере: `POST /api/fit` (МНК, Нелдер–Мид, границы из пресетов), кривые модели + точки данных на общем графике, «Пример» → `POST /api/fit/synthetic` (встроенный симулятор + шум, видно восстановление истинных параметров). **Далее** — верификация, анализ чувствительности, сценарный анализ; нейросеть (инверсное моделирование) — TensorFlow.js в браузере, обучается на синтетике симулятора, сравнивается с МНК.

## Соглашения

- Новые серверные модули — по образцу `core/*.ts` + роут в `app/api/*/route.ts` (формат ответа `{ok: boolean, ...}`, ошибки — `{ok: false, error: string}`).
- API-поля в snake_case (`raw_text`, `created_at`, `updated_at`).
- Новые клиентские разделы — страница в `client/src/pages/` + пункт в `NAV_ITEMS` (`app-shell.tsx`) + маршрут в `App.tsx`; ленивая загрузка (`React.lazy`).
- Тяжёлые вычисления — только на сервере; клиентские компоненты не должны дублировать симуляцию/анализ.
- Нейросети — TensorFlow.js в браузере, без Python-бэкенда.
- Каждая функция/метод — с коротким русским комментарием «зачем и как работает».
- `legacy/` — архив старого стека; изменения в нём допустимы только для сверки поведения.
