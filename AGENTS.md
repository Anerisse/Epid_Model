# AGENTS.md

Магистерская диссертация «Моделирование эпидемий». UI-строки и комментарии в коде на русском — сохраняйте это соглашение.

## Структура проекта

- `server/` — API на NestJS 11 + TypeORM + PostgreSQL. Здесь **единственный** `package.json` в репозитории; все npm-команды запускайте отсюда.
- `client/` — ванильный JS + Tailwind CDN. **Нет `package.json`, нет сборки.** Скрипты подключаются в фиксированном порядке в `index.html`: `keyboard.js`, `equations.js`, `diagram.js`, `main.js` (общие глобальные функции, без модулей). Кастомизация дизайна — инлайн-`<style>` в `index.html` + классы Tailwind.
- `docs/`, `diagrams/`, `plan/` — документация магистерской диссертации (docx/pdf/png/drawio), не код. Для разработки игнорируйте.

## Запуск приложения

Порядок важен — сервер не стартует без базы данных:

1. Поднимите Postgres. Предпочтительно через Docker: `docker compose up -d` (БД `epid_db` / пользователь `epid_user` / пароль `epid_pass`, порт 5432). Примечание: `docker` может отсутствовать в PATH оболочки — используйте полный путь `C:\Program Files\Docker\Docker\resources\bin\docker.exe` или добавьте его в PATH.
2. `npm install && npm run start:dev` в `server/`.
3. Раздайте `client/` статикой (например, `python -m http.server` из корня репозитория) или откройте `index.html`; CORS уже включён на сервере.

Особенности:

- Сервер слушает **порт 3001** (`process.env.PORT ?? 3001`), а не дефолтный для NestJS порт 3000. В клиенте адрес захардкожен в `client/js/equations.js`: `http://localhost:3001/api/models` — при смене порта меняйте в обоих местах.
- `.env` отсутствует; настройки БД задаются по умолчанию в `src/app.module.ts` (`DB_HOST`/`DB_PORT`/`DB_USER`/`DB_PASSWORD`/`DB_NAME`).
- **Важно**: после `git pull`/изменений перезапускайте сервер — он не подхватит новые модули без рестарта (в dev-режиме `start:dev` перезапускается сам, `node dist/main` — нет).

## Особенности бэкенда

- TypeORM работает с `synchronize: true` (только для разработки). **Миграций нет** — изменения сущностей автоматически применяются к схеме при запуске.
- Два рабочих модуля:
  - `equations/` — `GET/POST /api/equations` (старая сущность, одна строка текста; оставлена для обратной совместимости).
  - `models/` — `GET /api/models`, `GET /api/models/:id`, `POST`, `PATCH /:id`, `DELETE /:id`. Основное хранилище: сущность `models` (name, raw_text, structure JSONB, created_at, updated_at).
- Новые фичи делайте по образцу модулей `equations/` или `models/` (`*.module.ts` + `*.controller.ts` + `*.entity.ts`).
- Поля API в snake_case (`equation_text`, `created_at`, `raw_text`).

## Архитектура системы

Одна общая система «модель → этапы работы с ней». Каждый этап — **отдельный модуль**:

- на клиенте — раздел (вкладка) интерфейса с собственным экраном;
- на сервере — модуль NestJS со своими эндпоинтами.

В базовой поставке на каждый этап реализуется **по одному алгоритму**; архитектура рассчитана на расширение — подключение других алгоритмов не затрагивает остальную систему (пользователь может выбрать алгоритм в интерфейсе).

| Модуль | Раздел в клиенте | Сервер | Статус |
|---|---|---|---|
| Модель: ввод ОДУ, блок-схема, сохранение | «Модель» | `/api/models` | ⏳ в работе (парсер готов; **этап 2** — авто-блок-схема по потокам парсера + пунктирные дуги «силы заражения» от драйверов; ручные перенаправления потоков — fallback; полноценная редактируемая таблица потоков — далее) |
| Симуляция: численное интегрирование, графики S/I/R | «Симуляция» | — (на клиенте, без сервера) | ✅ сделано (**этап 4** — РК4 в браузере, `client/js/simulate.js`: ползунки параметров/начальных условий/горизонта, мгновенный пересчёт графиков) |
| Параметризация: оценка β, γ по данным | «Параметризация» | будущий модуль | 📋 план |
| Верификация: сравнение модели с данными | «Верификация» | будущий модуль | 📋 план |
| Анализ чувствительности: влияние параметров | «Анализ чувствительности» | будущий модуль | 📋 план |
| Сценарный анализ: сценарии вмешательств | «Сценарный анализ» | будущий модуль | 📋 план (соавтор) |

Нейросеть — отдельный блок в составе параметризации (**инверсное моделирование**: сеть восстанавливает параметры по наблюдаемой кривой). Планируется на TensorFlow.js прямо в браузере; обучающие данные генерируются встроенным симулятором (синтетические эксперименты), точность сравнивается с классическим алгоритмом (МНК).

## План развития (в общих чертах)

1. ✅ **Этап 0** — хранение структурированных моделей: сущность `models` + CRUD `/api/models`.
2. ✅ **Этап 1** — парсер системы ОДУ на клиенте (`client/js/parser.js`, чистый JS без DOM) + тесты через `node --test` без npm-зависимостей (`client/parser.test.js`). Разбирает `dS/dt = …`, `∂S/∂t = …`, `S' = …`, греческие буквы и алиасы (`beta`→`β`), строит AST, находит компартменты/параметры/потоки; структура сохраняется в `models.structure` при сохранении модели.
3. ⏳ **Этап 2** — авто-блок-схема компартментов на canvas. Сделано (`client/js/diagram.js`): схема рисуется по структуре парсера — компартменты из левых частей, потоки `inferFlows` (S→E→I→R для SEIR), топологическая сортировка блоков, перерисовка по дебаунсу + кнопка «Построить», тесты в `client/diagram.test.js`. Подписи потоков — «на единицу источника» (β*I/N, σ, γ, µ); потери вида µ*X (`to: null`) рисуются стрелкой «в никуда» вниз от блока (подпись µ — крупная и читаемая); пролёт через промежуточные блоки огибается дугой сверху. «Движители» потока (компартмент I в слагаемом β*S*I/N, `drivers` в структуре) рисуются пунктирной янтарной дугой от I к стрелке — «сила заражения»: люди переходят S→E, а I лишь задаёт скорость. Ручная правка потоков — через `FLOW_REDIRECTS` в `diagram.js` (пуст по умолчанию; полноценная редактируемая таблица потоков — далее).
4. ✅ **Этап 3** — интерфейс: тёмная тема, разделы под все модули, сохранение/загрузка/удаление моделей (см. `client/index.html`).
5. ✅ **Этап 4** — симуляция на клиенте (`client/js/simulate.js`, чистый JS без сборки): метод Рунге–Кутты 4-го порядка с фиксированным шагом `dt = 0.05`, правые части берутся из AST парсера и вычисляются через `evaluateExpression`. Раздел «Симуляция»: ползунок на каждый параметр модели (β, γ, σ, µ, N — из пресетов, неизвестные — общий диапазон), ползунки начальных условий S₀/E₀/I₀/R₀ (диапазон 0..N, по умолчанию S≈99%, I≈1%), горизонт времени 1–300 дней; движение любого ползунка мгновенно пересчитывает графики (дебаунс 80 мс). График на canvas: сетка, оси, кривые в цветах блок-схемы (переиспользуется `compartmentColor`), полупрозрачная заливка под кривыми, легенда и строка статистики (пик I, день пика, выздоровевшие). Ползунок N масштабирует начальные условия пропорционально (сумма остаётся ≈ N). При расходимости — понятное сообщение. Тесты в `client/simulate.test.js` (51/51 общий набор).
6. 📋 **Этап 5+** — параметризация (база — МНК, затем нейросеть); верификация; анализ чувствительности; сценарный анализ (вместе с соавтором над сценариями вмешательств).

Статусы: ✅ сделано, ⏳ в работе, 📋 запланировано. **Обновляйте этот файл при изменении плана** (периодически, по мере продвижения).

## Тесты и проверки

- В `server/` (обычные npm-команды):
  - `npm test` — unit-тесты; находятся как `*.spec.ts` внутри `src/`.
  - `npm run test:e2e` — поднимает **полный AppModule**, который подключается к Postgres: без запущенной БД эти тесты падают.
  - `npm run lint` — обратите внимание: по умолчанию включает `--fix`.
  - `npm run format` — Prettier (`prettier` с `endOfLine: "auto"`).
  - `dist/` присутствует в дереве; `npm start:prod` запускает `node dist/main`, поэтому после изменений пересобирайте через `npm run build`.
- Клиентские тесты без npm-зависимостей (из корня репозитория):
  - `node --test client/parser.test.js client/diagram.test.js client/simulate.test.js` — тесты парсера ОДУ (этап 1), раскладки блок-схемы (этап 2) и численного ядра симуляции (этап 4: РК4, сохранение популяции, пик эпидемии, убыль при μ, прерывание расходимости).

## Соглашения

- Новые модули — по образцу `equations/` или `models/`.
- API-поля в snake_case.
- Клиент без сборки: без import/export, только глобальные функции, порядок скриптов фиксирован (в `index.html`).
- Нейросети — TensorFlow.js в браузере, без Python-бэкенда.
- Каждая функция/метод — с коротким русским комментарием «зачем и как работает».
