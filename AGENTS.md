# AGENTS.md

Магистерская диссертация «Моделирование эпидемий». UI-строки и комментарии в коде на русском — сохраняйте это соглашение.

## Стек (после миграции)

Новый стек — клиент **React + TypeScript + Vite + TailwindCSS v4 + shadcn-стиль**, сервер **Next.js (App Router, API-роуты) + локальный SQLite** (`better-sqlite3`). Все тяжёлые вычисления — **на сервере**: разбор ОДУ, РК4, R₀ (NGM), МНК. Клиент только рендерит результаты (графики recharts, блок-схема SVG).

**Два пакета** (по одному `package.json` в каждом каталоге):

- `server/` — Next.js API + SQLite. `npm run dev` / `npm run build` / `npm start`.
- `client/` — Vite + React. `npx vite` (dev с прокси `/api` → 3001) / `npx vite build`.

Старый стек (ванильный JS-клиент + NestJS/Postgres) сохранён без изменений в `legacy/` (`legacy/client`, `legacy/server`) **только как эталон и архив** — не разрабатывается и не запускается. Его тесты (82/82 в legacy) побитово портированы на vitest в `server/core/*.test.ts` (47 тестов).

`docs/`, `diagrams/`, `plan/` — документация и материалы диссертации (docx/pdf/png/drawio), для разработки игнорируйте.

## Запуск приложения

База данных теперь не нужна отдельно (SQLite — файл `server/data/epid.db`, создаётся сам при первом обращении; `data/` в `.gitignore`).

1. Сервер: `cd server && npm install && npm run dev` — слушает **порт 3001** (`next dev -p 3001`).
2. Клиент: `cd client && npm install && npx vite --port 5173` — dev-сервер проксирует `/api` на `http://localhost:3001`.
3. Прод-режим: `cd server && npm run build && npm start` (порт 3001), клиент — `npx vite build` (папка `client/dist/`) раздаётся любым статиком.

Порты: сервер всегда 3001, прокси захардкожен в `client/vite.config.ts`. Менять порт — в обоих местах.

## Архитектура системы

Одна общая система «модель → этапы работы с ней»; **модель (текст ОДУ) — общий контекст** для всех разделов (React-контекст `client/src/lib/model-context.tsx`). Разбор текста выполняет сервер (`POST /api/parse`), клиент дебаунсит запросы.

Маршруты-разделы заданы списком (см. `client/src/components/app-shell.tsx`, роуты в `client/src/App.tsx`):

| Раздел | Маршрут | Сервер | Статус |
|---|---|---|---|
| Модель | `/` | `POST /api/parse` (структура+пресеты+раскладка+допущения), CRUD `/api/models` | ✅ сделано |
| Симуляция | `/simulation` | `POST /api/simulate` (РК4 на сервере: время/ряды/статистика + блок R₀) | ✅ сделано |
| Параметризация | `/parametrization` | `POST /api/fit` (МНК, Нелдер–Мид), `POST /api/fit/synthetic` | ✅ сделано |
| Верификация | `/verification` | будущий `POST /api/verify` | 📋 блоки-заглушки |
| Анализ чувствительности | `/sensitivity` | будущий `POST /api/sensitivity` | 📋 эскиз интерфейса |
| Сценарный анализ | `/scenario` | будущий `POST /api/scenario` | 📋 эскиз интерфейса (соавтор) |

В базовой поставке на каждый этап — по одному алгоритму; клиентские модули (`client/src/pages/*`) изолированы и могут расширяться без затрагивания остальных разделов.

### Сервер (`server/`)

- `core/` — **чистое ядро** (TS, без зависимостей от Next/React), 1-в-1 порт legacy-логики:
  - `parser.ts` — парсер систем ОДУ: `dS/dt`/`∂S/∂t`/`S'`, греческие буквы и алиасы (`beta`→`β`, `mu`→`μ` раньше анализа), алгоритм Пратта, AST, компартменты/параметры/потоки (`inferFlows`), `evaluateExpression`, `lightStructure` (без AST — то, что уходит в БД/на клиент).
  - `presets.ts` — пресеты ползунков (β 0.5/0–2, γ 0.2/0–1, σ 0.3/0–1, μ 0.02/0–0.5, α/δ/ε/λ 0.1/0–1, N 10000/1000–1e5; `GENERIC_PARAM_PRESET` 0.1/0–1; `DEFAULT_POPULATION` 10000). У каждого пресета есть `unit` для подписи на клиенте: скоростные коэффициенты — «1/день», N/n — «чел.»; `isPopulationParam` помечает N/n.
  - `diagram.ts` — топологическая сортировка (алгоритм Кана), раскладка блоков, цвета; **SVG по координатам рисует клиент** (`client/src/components/block-diagram.tsx`): дуги-стрелки, обход промежуточных блоков дугой сверху, пунктирные янтарные «силы заражения» (движители вроде I в β*S*I/N), потери «в никуда» (µ*X) со стрелкой вниз и «таблеткой» под подписью. Ручные перенаправления потоков — `FLOW_REDIRECTS` (пуст; полноценная редактируемая таблица потоков — далее).
  - `simulate.ts` — РК4 с шагом `SIM_DT = 0.05`, расходимость кидает понятную ошибку; статистика (пик I, день пика, выздоровевшие) и `buildAnalysisReport` — **блок «Качественный анализ»**.
  - `analysis.ts` — R₀ универсально методом NGM по правым частям ОДУ (классификация компартментов с замыканием цепочек, `ρ(F·V⁻¹)`), мини-КАС **символьного вывода «уравнения R₀»** (`derive`, `simplify`, `formulaText`; для 2 заражённых — tr/√(tr²−4det), формула принимается только при совпадении с численным NGM), порог 1/R₀, итог переболевших из `1−x = e^(−R₀·x)`, проверка сохранения популяции, ручная формула `computeR0Manual`.
  - `fit.ts` — МНК: `parseFitData` («день число»/одиночные числа), `fitInitialCondition` (I₀ из первого наблюдения), `simulateAtDays`, `fitCost`, Нелдер–Мид без производных (`nelderMead`, границы из пресетов), `fitParameters` (N подставляется автоматически), `generateSyntheticData` (истинные параметры = пресеты + шум).
  - `labels.ts` — **пользовательские названия терминов**: типы `TermLabel { ru, en }` / `LabelsMap` и `sanitizeLabels` (чистка входа: только строки, обрезка длины, пустые названия не хранятся).
  - `assumptions.ts` — **блок «Допущения модели»**: `detectAssumptions` по разобранной системе предлагает 4 галочки (замкнутая популяция — нет μ/Λ; нет латентного периода — прямой поток S→I; постоянная передача — нет зависимости от t; однородное перемешивание — нет параметра A/age) с пояснением `evidence`, флагом `auto` (автоматика уверена) и текстами предупреждений `warnings.checked` / `warnings.unchecked` на случай расхождения выбора с уравнением. `sanitizeAssumptions` чистит состояние из API/БД: только известные id, только boolean, заметки ≤ 5000 символов.
- `lib/db.ts` — SQLite (better-sqlite3): таблица `models` (id, name, raw_text, structure JSON-строка, **labels JSON-строка** — названия компартментов и параметров, **assumptions JSON-строка** — допущения и заметки, created_at, updated_at; поля API в snake_case), CRUD-хелперы. Миграции: если колонок `labels`/`assumptions` ещё нет — `ALTER TABLE models ADD COLUMN …` (проверка через `PRAGMA table_info`). Путь БД — `server/data/epid.db` (переопределяется `DB_PATH`/`DB_DIR`).
- `app/api/` — роуты App Router, везде `export const dynamic = "force-dynamic"` (без кэширования):
  - `models/route.ts` и `models/[id]/route.ts` — GET/POST и GET/PATCH/DELETE (структуру считает парсер при сохранении; `labels` и `assumptions` принимаются и в POST, и в PATCH).
  - `parse/route.ts` — `{ok, structure(light), presets, assumptions, diagram}`.
  - `simulate/route.ts` — принимает «сырой» текст + параметры/начальные условия/горизонт/ручную формулу, парсит сам; возвращает `{ok, time, series, names, colors, rhsText, stats, analysis}` (R₀ встроен в ответ симуляции).
  - `fit/route.ts` — `{ok, params, rmse, r2, iterations, time, model(кривая I), points}`; `fit/synthetic/route.ts` — `{ok, text, params}`.
- `next.config.mjs` — `serverExternalPackages: ["better-sqlite3"]` (нативный модуль не бандлится). Порядок скриптов: `dev`/`build`/`start` (`-p 3001`), `test` (vitest `run` в `core/`).

### Клиент (`client/`)

- Vite + React 19 + react-router-dom v7 + recharts + lucide-react + tailwindcss v4 (`@tailwindcss/vite`, тема в `src/index.css` через `@theme`: палитра `ink`, шрифты Manrope/Space Grotesk/JetBrains Mono; стили range-слайдеров `.sim-range`).
- `src/lib/api.ts` — типизированные HTTP-хелперы к `/api` (зеркало серверных типов).
- `src/lib/model-context.tsx` — общий контекст модели: текст+название, автозагрузка последней сохранённой, дебаунс-разбор через `/api/parse`, список сохранённых моделей, результат последней оценки параметров (`fitResult` — кладётся страницей параметризации, сбрасывается при смене текста модели), **названия терминов** (`labels: LabelsMap` — символ → {ru, en}), **допущения модели** (`assumptionChecks` — подсказки из разбора, `assumptions: AssumptionsState` — подтверждённые галочки и свободные заметки) и `currentId` (id текущей модели в БД). Методы: `save(opts?)` (создать; можно передать имя/текст/названия/допущения — из окна редактора), `updateModel(id, patch)` (обновить запись), `load(m)` (загрузить запись вместе с названиями и допущениями), `setAssumptions(a)` (меняет состояние сразу, а для сохранённой модели тихо пишет в БД с дебаунсом 600 мс — только если текст в редакторе совпадает с сохранённым, чтобы не записать подсказки новой модели в старую; чтобы не писать на каждый символ в заметках).
- `src/lib/theme.tsx` — **тема оформления**: тёмная (по умолчанию) и светлая; переключение — класс `.light` на `<html>`, который переопределяет CSS-переменные палитры в `index.css` (инвертируется «серая» шкала + приглушаются акценты). Выбор хранится в `localStorage` (`simula-theme`), применяется до первой отрисовки скриптом в `index.html` (без «мигания»), глобально ставится `color-scheme` для нативных контролов. Все утилиты Tailwind работают в обеих темах без дублирования разметки; цвета recharts и SVG-блок-схемы берутся из темы (`useTheme()` / `var(--color-…)`). Поверхности выстроены по слоям (фон приложения → карточка → вложенный блок), чтобы интерфейс не был «белым на белом»: классы `.surface-card` (карточка: тень в тёмной теме, плоская белая панель с рамкой — в светлой), `.surface-float` (плавающие панели: мягкая тень в обеих темах), `.app-header` / `.app-sidebar` (полосы каркаса), `.nav-item-active` (активный пункт меню).
- `src/components/app-shell.tsx` — каркас: **верхняя панель на всю ширину** («Simula» + подпись «моделирование эпидемий», по центру — статус модели, справа — переключатель темы и кнопки «Войти»/«Регистрация» — заглушка) + левая панель вкладок разделов + контент. Панель разделов сворачивается **«язычком» на её кромке** (узкая вертикальная вкладка `h-16 w-4` с полукруглым правым краем и `ChevronLeft`/`ChevronRight`, стоит под шапкой): у открытой панели он вплотную за правым краем (`left-64`, без наложения на панель), у скрытой — у левого края экрана (`left-0`); ширина плавно анимируется (`w-64` ↔ `w-0`, `transition-[width]`), у скрытой панели `inert` и `aria-hidden` (фокус и скринридеры её не видят), контент занимает освободившееся место, а страницы держат отступ `p-5` (20 px), чтобы язычок не наезжал на карточки. Контент — 100dvh, страницы раскладываются на панели и скроллятся внутри них (без прокрутки всей страницы на десктопе).
- `src/components/model-status.tsx` — **статус текущей модели в шапке** (заменил вертикальную вкладку-рейл у правого края): в одной строке — подпись «Модель», название модели (или список компартментов), число пройденных этапов (`N/4`) и пилюля статуса «черновик / в работе / готова». По нажатию раскрывается карточка с дорожной картой работы: «Введена» → «Заданы названия компартментов» → «Отпараметризована» → «Верифицирована» (состояние вычисляется из общего контекста модели: текст, структура, `fitResult`; в карточке этапы отмечены галочками/кружками, в компактной строке шапки кругов нет); **внутри карточки — карандаш** «Назвать термины и изменить уравнение», открывающий окно редактора модели (`model-editor-dialog.tsx`), и кнопка «Открыть раздел «Модель»». Закрывается по клику вне, `Escape` и повторному нажатию. Шапка имеет `relative z-30`, поэтому карточка рисуется поверх контента и не обрезается.
- `src/components/model-editor-dialog.tsx` — **окно редактирования модели**: название, текст системы ОДУ, таблица названий компартментов/параметров (рус. и англ.) и блок «Допущения модели» — термины и подсказки по допущениям подбираются разбором текста (`/api/parse`, дебаунс 300 мс), допущения правятся локально. Кнопки: «Сохранить в базу» (PATCH для записи из БД, иначе создание новой; уходят и названия, и допущения), «В редактор модели» (перенос правок в рабочую модель), «Отмена». Открывается по клику на модель в списке сохранённых и по карандашу в карточке статуса модели в шапке (`model-status.tsx`). Окно рендерится **порталом в `document.body`** и начинается ниже шапки (`pt-20`, `max-h-[calc(100dvh-6rem)]`): иначе `position: fixed` считается от шапки с `backdrop-blur` и окно обрезается её высотой.
- `src/components/on-screen-keyboard.tsx` — экранная клавиатура (порт legacy `keyboard.js`): **плавающая панель у нижнего края экрана** (`fixed bottom-4`, как было до переезда), не модальное окно; секции «Ввод» (шаблоны `dX/dt` и `∂X/∂t` + цифры/операторы), латинские заглавные (компартменты), греческие (параметры), символы; вставка в позицию курсора textarea.
- `src/components/model-assumptions.tsx` — **блок «Допущения модели»** (управляемый компонент: подсказки `checks`, состояние `value`, `onChange`, `idPrefix`, поэтому используется и на странице «Модель», и в окне редактора модели) на странице «Модель» в правой колонке: на широком окне — справа от «Структуры модели», на узком — под ней; так он не отнимает высоту у списка сохранённых моделей слева. Часть А — 4 автоматические галочки из `assumptionChecks` (по умолчанию отражают подсказку, ручной выбор хранится в `assumptions.items`; всегда **одним столбцом**, без разбиения на колонки; карточка — `h-full`, т.е. растягивается на высоту строки, поэтому её нижний край всегда совпадает с «Структурой модели»), бейдж «вручную» при `auto = false` и иконка «вернуть авто»; часть Б — янтарное предупреждение, если ручной выбор расходится с уравнением (только при уверенной автоматике); часть В — свободное поле «Дополнительные допущения» (`assumptions.notes`, ≤ 5000 символов), которое **свёрнуто по умолчанию** и раскрывается по «+» (если заметки уже есть — показывается их краткий предпросмотр, поле открыто). Блок компактный: общее описание, пояснения к пунктам и подсказка о попадании в отчёт — в иконках «?» при наведении (`ui/hint.tsx`, портал поверх страницы), а не постоянным текстом; в одну колонку блок занимает ~263–290 px; раскрытое поле заметок добавляет ~100 px.
- `src/components/ui/hint.tsx` — иконка «?» с всплывающей подсказкой: портал в `document.body`, позиционирование рядом с иконкой (при нехватке места снизу — вверх, у края экрана прижимается), закрытие по уходу курсора, `Escape`, прокрутке и изменению размера; работает и с клавиатуры (focus/blur).
- `src/components/ui/*` — shadcn-стиль Компонентов написаны вручную (cn/cva, без Radix; чекбоксы и слайдеры — нативные).
- `src/components/plan-ui.tsx` — общие элементы эскизов разделов: `BlockStub` (пунктирный блок «здесь появится…»), `PlanChip` (чип будущей настройки с тонами `default/emerald/amber/sky/rose`) и `MockTable` (пустая таблица с известными колонками и подписями строк). Используются в эскизах анализа чувствительности и сценарного анализа.
- **Адаптивность раскладки**: при ширине окна < `xl` (1280 px) блоки разделов идут друг за другом (одна колонка, страница скроллится целиком), на широком экране — две колонки во всю высоту. Сделано через `auto-rows-min content-start` в базовых классах грида и сброс `xl:auto-rows-auto xl:content-normal` (иначе строки грида с заданной высотой растягиваются и содержимое блоков наезжает друг на друга). На странице «Модель» левая колонка — редактор и список сохранённых моделей, правая — сетка: при ширине окна ≥ 1390 px «Структура модели» и «Допущения модели» стоят рядом (структура — `1fr`, допущения — `clamp(300px, max(21vw, 100% - 512px), 580px)`: структуре всегда остаётся ~500 px, остальное до 580 px забирают допущения; обе карточки растягиваются на высоту строки — у допущений `h-full`, — поэтому нижние края совпадают при любой длине структуры), уже — допущения уходят под структуру; в «Структуре модели» на широкой карточке (контейнер ≥ 460 px, т.е. окно примерно от 1800 px) подписи «Компартменты», «Параметры», «Потоки» встают отдельной строкой над значениями (`@container` + `@min-[460px]:w-full`), на узкой — в одну строку со значениями; блок-схема занимает оставшуюся высоту во всю ширину правой колонки, но не ниже `xl:min-h-[340px]`. Если места совсем мало, правая колонка прокручивается, а не сжимает схему.

## План развития

1. ✅ **Этап 0** — хранение моделей: таблица `models` + CRUD `/api/models` (SQLite вместо Postgres).
2. ✅ **Этап 1** — парсер ОДУ на сервере (`server/core/parser.ts`) + тесты vitest; разбор SIR/SEIR/…, греческие буквы и алиасы, компартменты/параметры/потоки, `structure` в `models.structure`.
3. ✅ **Этап 2** — авто-блок-схема: раскладка и потоки на сервере (`diagram.ts`), отрисовка SVG на клиенте (`block-diagram.tsx`) — дуги, обходы, пунктирные «силы заражения», потери; ручные перенаправления `FLOW_REDIRECTS` — fallback; редактируемая таблица потоков — далее.
4. ✅ **Этап 3** — интерфейс: тёмная тема, верхняя панель с названием системы и вкладки-разделы, сохранение/загрузка/удаление моделей, страницы в один экран; блок «Допущения модели» на странице «Модель» (авто-подсказки, предупреждения о расхождениях, свободные заметки — хранятся в БД вместе с моделью).
5. ✅ **Этап 4** — симуляция на сервере: `POST /api/simulate` (РК4 с `dt = 0.05` в `simulate.ts`), графики S/E/I/R в recharts по цветам блок-схемы, статистика (пик I, день пика, выздоровевшие). **Блок «Качественный анализ»** — в том же ответе: R₀ методом NGM (универсально, без ручных формул), символьное «уравнение R₀» (мини-КАС в `analysis.ts`), F/V-матрицы, вердикт, порог 1/R₀, итог переболевших, сохранение популяции, ручная формула как fallback.
6. ✅ **Этап 5** — параметризация на сервере: `POST /api/fit` (МНК, Нелдер–Мид, границы из пресетов), кривые модели + точки данных на общем графике, «Пример» → `POST /api/fit/synthetic` (встроенный симулятор + шум, видно восстановление истинных параметров). **Далее** — верификация (состав блоков зафиксирован: данные верификации, проверяемая модель, структурные проверки, сверка с наблюдениями, метрики согласия, остатки, кросс-валидация, итоговый вердикт), анализ чувствительности и сценарный анализ (эскизы интерфейса готовы по требованиям `Docs/SA Scenario` — остались серверные расчёты); нейросеть (инверсное моделирование) — TensorFlow.js в браузере, обучается на синтетике симулятора, сравнивается с МНК.

## Соглашения

- Новые серверные модули — по образцу `core/*.ts` + роут в `app/api/*/route.ts` (формат ответа `{ok: boolean, ...}`, ошибки — `{ok: false, error: string}`).
- API-поля в snake_case (`raw_text`, `created_at`, `updated_at`).
- Новые клиентские разделы — страница в `client/src/pages/` + пункт в `NAV_ITEMS` (`app-shell.tsx`) + маршрут в `App.tsx`; ленивая загрузка (`React.lazy`).
- Тяжёлые вычисления — только на сервере; клиентские компоненты не должны дублировать симуляцию/анализ.
- Нейросети — TensorFlow.js в браузере, без Python-бэкенда.
- Каждая функция/метод — с коротким русским комментарием «зачем и как работает».
- `legacy/` — архив старого стека; изменения в нём допустимы только для сверки поведения.
