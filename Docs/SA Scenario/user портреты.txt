Пользовательские портреты для анализа чувствительности и сценарного анализа
1.	Эпидемиолог-исследователь

Роль: сотрудник научно-исследовательского института (НИИ) лаборатории математического моделирования эпидемий. Имеет публикации, участвует в грантах, готовит статьи в рецензируемые журналы.
Цели: понять, какие параметры модели определяют поведение системы, и обосновать это. Ему нужно их получить с соблюдением методологических требований, сравнить применяемые методы анализа чувствительности, оценить корректность выводов. 
Дополнительная цель – подготовить модель к использованию аналитиком: выделить управляющие параметры, обосновать их выбор, передать результаты внутрь системы.
Уровень подготовки: высокий в области эпидемиологии и математического моделирования, но без навыков программирования. Готов работать со сложными настройками, если интерфейс интуитивно-понятный.
Боли: для работы в существующих программных инструментах нужны знания языков программирования или, наоборот, в них реализованы только базовые модели, которые не позволяют спрогнозировать полную эпидемиологическую ситуацию.
Требования к системе:
	3 метода анализа чувствительности (OAT+торнадо диаграмма, метод Морриса, метод Соболя);
	Автоматический или ручной выбор метода, настройка параметров;
	Сравнение методов в одном виде (без ручного сведения таблиц);
	Отсутствие долгих расчетов, видение прогресса, возможность отменить расчеты;
	Сохранение текущей конфигурации (модель + данные + параметризация + верификация + анализ чувствительности), комментарии к результатам;
	Экспорт в JSON / CSV для дальнейшей обработки.
2.	Аналитик

Роль: сотрудник НИИ, в отделе эпидемиологического анализа или в группе поддержки принятия решений. Работает «на стыке»: получает запросы от органов управления здравоохранения (через руководство НИИ) и превращает их в обоснованные расчеты и отчеты.
Цели: быстро построить несколько сценариев и получить обоснованную рекомендацию, которую можно оформить в отчёт для руководства. Отвечает на запросы вида «Что, если..?».
Уровень подготовки: средний/высокий в моделировании эпидемий. Высокий – в управлении принятия решений. Ценит простоту, наглядность, скорость получения результата.
Боли: нет инструмента для быстрого формирования сценариев с текстовой интерпретацией. 
Требования к интерфейсу:
	Доступ к готовым конфигурациям (модель + данные + параметризация + верификация + анализ чувствительности);
	Отображение результатов SA рядом с параметрами;
	Оптимизация с ограничениями (SLSQP) для расчетов в определенном временном промежутке или при фиксированном бюджете;
	Три режима сценариев (ручной / сравнение / оптимальное);
	Сравнение 2–5 сценариев в одном окне;
	Диаграмма «затраты-выгода»;
	Быстрая проверка устойчивости (Моррис);
	Сохранение и клонирование прогонов расчетов;
	Генерация PDF по шаблону с интерпретацией результатов;

Пользовательские сценарии
Сценарий 1. «Анализ чувствительности» (Эпидемиолог-исследователь).
Пользователь:
1.	Открывает модель, которую откалибровал. Видит метрики, статус, версию.
2.	Настраивает анализ чувствительности:
	Выбирает целевую переменную (J, заболеваемость, смертность, доля MDR).
	Задаёт диапазоны параметров (не только min/max, но и распределение – равномерное, нормальное, логнормальное).
	Выбирает метод (или «Авто» – система предложит).
	Задаёт бюджет времени и точность.
3.	Запускает расчёт. Видит прогресс, может отменить. Результаты кэшируются.
4.	Смотрит результаты:
	Торнадо диаграмма (OAT);
	По методу Морриса;
	По методу Соболя;
	Таблицу, ранжированную по эффективности параметра.
5.	Сравнивает методы. Открывает вид «Сравнение» – три метода рядом, ранги, совпадения топ-3, стоимость в прогонах.
6.	Проверяет устойчивость. Меняет размер выборки (N = 100, 500, 1000, 5000), смотрит, как стабилизируются индексы чувствительности. Меняет диапазоны – смотрит, как меняется ранжирование.
7.	Экспортирует:
	CSV/JSON с индексами и ДИ – для дальнейшей обработки.
	Конфигурация прогона – для воспроизводимости.
8.	Помечает результат как «готов для сценариев». Система сохраняет ранжирование и привязывает его к модели. Аналитик увидит эти данные, когда откроет модуль сценариев.
9.	Оставляет комментарий к результату – например, «βS доминирует, но взаимодействия с qS значимы (STi − Si = 0.04)». Это попадёт в отчёт аналитика.

Сценарий 2. «Сценарный анализ» (Аналитик).
Пользователь:
1.	Открывает список моделей. Видит только те, что помечены исследователем как «готовы для сценариев».
2.	Выбирает модель. Видит её версию, метрики, автора, а также результаты анализа чувствительности – какие параметры важны и почему.
3.	Настраивает сценарии:
Горизонт (обычно 3–5 лет).
Веса w1, w2 (или берёт по умолчанию).
Бюджетные ограничения.
Режим: ручной / сравнение / оптимальное управление.
4.	Выбирает управляющие параметры – из списка, предложенного системой на основе анализа чувствительности. Видит индексы чувствительности рядом с каждым.
5.	Запускает расчёт. Видит прогресс, может отменить.
6.	Смотрит результаты:
Графики заболеваемости и смертности по сценариям.
Сравнительную таблицу.
Диаграмму «затраты-выгода».
Оптимальные траектории u(t).
7.	Проверяет устойчивость – запускает быстрый Моррис для проверки, что вывод не случаен.
8.	Сохраняет отчёт PDF по шаблону: резюме, постановка задачи, модель, сценарии, сравнение, рекомендация.
9.	При запросе «а посчитайте ещё вариант» – открывает сохранённый прогон, клонирует, меняет один параметр, считает, генерирует дополнение к отчёту.
