# Моделирование эпидемий

Магистерская диссертация «Моделирование эпидемий»: система «модель → этапы работы с ней».
Модель (система ОДУ) — общий контекст для всех разделов; тяжёлые вычисления выполняются на
сервере, клиент только настраивает прогон и показывает результат.

## Разделы

| Раздел | Маршрут | Что делает | Сервер | Статус |
|---|---|---|---|---|
| Модель | `/` | Разбор ОДУ, блок-схема, допущения, названия терминов, сохранение моделей | `POST /api/parse`, CRUD `/api/models` | ✅ |
| Симуляция | `/simulation` | РК4, графики компартментов, статистика, блок «Качественный анализ» (R₀, NGM) | `POST /api/simulate` | ✅ |
| Параметризация | `/parametrization` | МНК + Нелдер–Мид, кривая модели по наблюдениям, синтетический пример | `POST /api/fit`, `POST /api/fit/synthetic` | ✅ |
| Верификация | `/verification` | Эскиз: данные, структурные проверки, метрики согласия, остатки, кросс-валидация, вердикт | будущий `POST /api/verify` | 📋 |
| Анализ чувствительности | `/sensitivity` | Эскиз: OAT/торнадо, Моррис, Соболь, сравнение методов, устойчивость | будущий `POST /api/sensitivity` | 📋 |
| Сценарный анализ | `/scenario` | Эскиз: сценарии вмешательств, режимы ручной/сравнение/оптимальный, «затраты-выгода» | будущий `POST /api/scenario` | 📋 |

## Стек

- **Клиент** — React 19 + TypeScript + Vite + TailwindCSS v4, компоненты в стиле shadcn,
  графики recharts, блок-схема — SVG.
- **Сервер** — Next.js (App Router, API-роуты) + локальный SQLite (`better-sqlite3`).
  Здесь же парсер ОДУ, РК4, R₀ методом NGM и МНК.
- **База** — файл `server/data/epid.db`, создаётся автоматически при первом обращении.
  Отдельный сервер БД и Docker не нужны.

## Структура репозитория

```
client/        React-приложение (Vite), отдельный package.json
server/        Next.js API + SQLite + чистое ядро core/ (парсер, симуляция, анализ, МНК)
legacy/        Архив старого стека (vanilla JS + NestJS/Postgres) — только для сверки, не запускается
Docs/          Документация диссертации (docx/pdf/png/drawio)
Diagrams/      Схемы
Plan/          Материалы планирования
docker-compose.yml  Остаток legacy-стека (Postgres) — текущему приложению не нужен
AGENTS.md      Соглашения разработки и карта кода
```

## Требования

- **Node.js 20+** и npm.
- Браузер (Chrome/Edge/Firefox).
- Docker/PostgreSQL **не требуются**: база — локальный файл SQLite.

## Запуск

### 1. Сервер (порт 3001)

```bash
cd server
npm install
npm run dev
```

Сервер поднимется на `http://localhost:3001`, база создастся сама в `server/data/epid.db`.

Путь к базе можно переопределить переменными окружения:

- `DB_DIR` — каталог для `epid.db`;
- `DB_PATH` — полный путь к файлу базы.

### 2. Клиент (порт 5173)

В отдельном терминале:

```bash
cd client
npm install
npx vite --port 5173
```

Откройте `http://localhost:5173`. Dev-сервер Vite проксирует `/api` на
`http://localhost:3001` (см. `client/vite.config.ts`).

### Продакшн-режим

```bash
cd server
npm run build
npm start          # порт 3001

cd client
npx vite build     # результат — client/dist/
```

`client/dist/` раздаётся любым статическим сервером. Важно: клиент обращается к API по
относительному пути `/api`, поэтому на том же домене нужен reverse proxy на сервер
(например, nginx: `location /api/ { proxy_pass http://localhost:3001; }`).

### Порты

| Что | Порт |
|---|---|
| API (Next.js) | 3001 |
| Клиент (Vite dev) | 5173 |

Порт сервера задан в `server/package.json` (`next dev -p 3001`), прокси — в
`client/vite.config.ts`. При смене порта меняйте оба места.

## API

Все ответы — JSON, ошибки — `{ ok: false, error: string }`. API-поля в `snake_case`.

| Метод и путь | Назначение |
|---|---|
| `POST /api/parse` | Разбор текста ОДУ: структура, пресеты параметров, раскладка блок-схемы, допущения |
| `POST /api/simulate` | РК4 по модели: время, ряды, статистика, R₀ и качественный анализ |
| `POST /api/fit` | Оценка параметров по наблюдениям (МНК, Нелдер–Мид) |
| `POST /api/fit/synthetic` | Синтетические данные для демонстрации параметризации |
| `GET /api/models` | Список сохранённых моделей |
| `POST /api/models` | Создать модель |
| `GET /api/models/:id` | Модель по id |
| `PATCH /api/models/:id` | Обновить модель (текст, названия, допущения) |
| `DELETE /api/models/:id` | Удалить модель |

## Тесты и проверки

```bash
# ядро сервера (парсер, блок-схема, симуляция, R₀, МНК, допущения)
cd server
npm test

# типы и сборки
cd server && npx tsc --noEmit
cd client && npx tsc --noEmit

cd server && npm run build
cd client && npm run build
```

Тесты не требуют базы данных и внешних сервисов. Смоук-тест API удобно делать при
запущенном сервере: `POST /api/parse`, `/api/simulate`, `/api/models`, `/api/fit`
(например, для SEIR при β = 0.5 и γ = 0.2 ожидается R₀ ≈ 2.5).

## Docker

`docker-compose.yml` в корне поднимает `postgres:15` — это часть **старого** стека
(`legacy/server`). Текущий сервер к Postgres не подключается: модели хранятся в SQLite,
поэтому запускать compose для работы приложения не нужно.

Если приложение всё же упаковывается в контейнеры:

- смонтируйте каталог с базой (например, volume на `/data` и `DB_DIR=/data`), иначе
  модели исчезнут при пересоздании контейнера;
- в клиенте проксируйте `/api` на имя сервиса (`http://server:3001`), а не на
  `localhost` — внутри контейнера `localhost` указывает на сам клиентский контейнер.

## Частые проблемы

- **Модели не сохраняются / список пуст** — сервер не запущен или смотрите не тот файл
  базы. Проверьте `http://localhost:3001/api/models` и `server/data/epid.db`.
- **Клиент не видит API** — запущен ли сервер на 3001 и используется ли dev-сервер Vite
  (прокси `/api` работает только в dev-режиме и только на порту 5173).
- **Ошибка нативного модуля `better-sqlite3`** — пересоберите под текущую версию Node:
  `cd server && npm rebuild better-sqlite3`.
- **Порт занят** — 3001 (API) или 5173 (клиент). Освободите порт или измените его сразу
  в `server/package.json` и `client/vite.config.ts`.
- **Не разбирается уравнение** — проверьте синтаксис: `dS/dt = …`, `∂S/∂t = …` или
  `S' = …`; поддерживаются греческие буквы и алиасы (`beta` → `β`).
