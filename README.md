# Моделирование эпидемий

Магистерская диссертация «Моделирование эпидемий»: система «модель → этапы работы с ней». Каждый этап — отдельный модуль
с собственным разделом интерфейса и (для серверных частей) эндпоинтами.

| Этап | Что делает | Статус |
|---|---|---|
| 1. Парсер ОДУ | Разбирает `dS/dt = …`, `∂S/∂t = …`, `S' = …`, строит AST, находит компартменты/параметры/потоки | ✅ |
| 2. Блок-схема | Авто-схема компартментов на canvas, дуги «силы заражения» | ✅ |
| 3. Интерфейс | Тёмная тема, разделы под все модули, сохранение моделей в БД | ✅ |
| 4. Симуляция | Рунге–Кутта 4 в браузере, графики S/E/I/R, ползунки параметров | ✅ |
| 5+ | Параметризация (МНК → нейросеть), верификация, чувствительность, сценарии | 📋 план |

## Структура

- `server/` — API на NestJS 11 + TypeORM + PostgreSQL. **Единственный** `package.json` в репозитории; все npm-команды — отсюда.
- `client/` — ванильный JS + Tailwind CDN. **Без сборки**: скрипты подключаются в `index.html` в фиксированном порядке.
- `docs/`, `diagrams/`, `plan/` — документация магистерской диссертации (docx/pdf/png/drawio), к запуску отношения не имеет.

## Что нужно установить

| Компонент | Зачем | Когда нужен |
|---|---|---|
| **Node.js 18+** (лучше 20 LTS) | сервер NestJS и клиентские тесты | всегда |
| **Docker Desktop** ИЛИ **PostgreSQL 15** | база данных `epid_db` | только для сохранения моделей через сервер |
| **Python 3** | раздача `client/` статикой (`python -m http.server`) | только для сервера/клиента вместе; можно и без него |
| Браузер (Chrome/Edge/Firefox) | интерфейс | всегда |

> **Симуляция (этап 4) работает вообще без сервера и БД** — весь расчёт идёт в браузере.
> Сервер и Postgres нужны только для сохранения/загрузки моделей.

## Запуск

### Вариант 1 — полностью (с сохранением моделей)

Порядок важен: сервер не стартует без базы данных.

**1. Клонируйте проект и зайдите в него**

```bash
git clone <адрес вашего репозитория>
cd Epid_Model
```

**2. Поднимите PostgreSQL (контейнер и есть Postgres — скачивать отдельно не нужно)**

```bash
docker compose up -d
```

В первый раз Docker сам скачает образ `postgres:15` и создаст БД `epid_db`,
пользователя `epid_user` с паролем `epid_pass`, порт 5432.

> На Windows `docker` может не быть в PATH оболочки — используйте полный путь
> `C:\Program Files\Docker\Docker\resources\bin\docker.exe up -d`
> или добавьте Docker в PATH.

Проверка: `docker compose ps` — контейнер `db` должен быть `Up`.

**3. Запустите API (порт 3001)**

```bash
cd server
npm install
npm run start:dev
```

Ждите строку `Server is running on http://localhost:3001`. Таблицы в БД создаются
сами (`TypeORM synchronize: true`, для разработки).

> Настройки БД берутся из `server/src/app.module.ts`: можно переопределить
> переменными `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME`.

**4. Раздайте клиент статикой (порт 8080)**

В отдельном терминале, из корня репозитория:

```bash
python -m http.server 8080
```

**5. Откройте интерфейс**

`http://localhost:8080/client/index.html` (при первом открытии — **Ctrl+F5**, чтобы
сбросить кэш скриптов).

### Вариант 2 — только симуляция (без сервера и БД)

Шаги 2 и 3 не нужны. Достаточно шага 4 (или просто открыть `client/index.html`
двойным кликом — CORS на симуляцию не влияет, API не вызывается).

## Проверка работоспособности

- Раздел «Модель»: введите SIR, нажмите «Построить» → блок-схема. «Сохранить модель» → модель появится в списке (только при запущенном сервере).
- Раздел «Симуляция»: кнопка «Следующий шаг →» из раздела «Модель»; двигайте ползунки β, γ, σ, N — графики пересчитываются мгновенно.

## Тесты

Из корня репозитория (без npm-зависимостей):

```bash
node --test client/parser.test.js client/diagram.test.js client/simulate.test.js
```

В `server/`:

```bash
cd server
npm test          # unit-тесты
npm run lint      # внимание: включает --fix
npm run format    # Prettier
```

`npm run test:e2e` поднимает полный AppModule и **требует запущенной БД**.

## Частые проблемы

- **Сервер не стартует** — не запущена БД: сначала `docker compose up -d` и дождитесь готовности контейнера (`docker compose ps`).
- **Нет реакции интерфейса на изменения** — кэш браузера: Ctrl+F5. Сервер `start:dev` перезапускается сам при правках; `node dist/main` (продакшн) — нет, пересоберите `npm run build`.
- **Порт занят** — 3001 (API), 5432 (БД), 8080 (статика). Адрес API захардкожен в `client/js/equations.js` (`http://localhost:3001/api/models`) — при смене порта меняйте в обоих местах.
